01

What is Convolution?

In image processing, convolution is the process of sliding a small matrix called a kernel across the entire input image and computing a weighted sum at each position. Each result becomes one value in the output — called the feature map.

Unlike a fully-connected layer that assigns a separate weight to every pixel, a convolutional layer reuses the same kernel everywhere. This is called parameter sharing — and it's why CNNs can process high-resolution images with far fewer parameters.

💡 Analogy

Imagine holding a stamp over a photograph and pressing it down at every position — left to right, top to bottom. Each imprint reveals a different pattern. That stamp is your kernel; the collection of imprints is your feature map.

Output(i, j) = Σm Σn   Input(i+m, j+n) × Kernel(m, n)

WHY 3×3?

Two stacked 3×3 convolutions cover the same receptive field as one 5×5, but with 18 vs 25 parameters — plus an extra non-linearity. Modern networks like VGG use almost exclusively 3×3 kernels for exactly this reason.

DEPTH = CHANNELS

A real kernel has depth equal to the input channels. For RGB, each kernel is 3×3×3 = 27 weights, and results across channels are summed to produce a single output feature map.

04

Stride & Padding

Stride controls how many pixels the kernel jumps at each step. Stride 1 = one pixel at a time (dense coverage). Stride 2 = skip every other position, roughly halving the output size. Larger stride means smaller feature maps and lower computation, but coarser detail.

Padding adds a border of zeros around the input before convolving. Without it the output shrinks each layer. With same padding the output stays the same spatial size as the input — essential when stacking many conv layers.

Stride = 1

Kernel moves one pixel at a time. Dense coverage, maximum output resolution.

Stride = 2

Kernel jumps two pixels (red = skipped positions). Output is roughly half the size.

No Padding (Valid)

6×6 input with a 3×3 kernel → only the inner 4×4 positions are valid (purple).

Same Padding

Zero-border (dim) added around the input so the output keeps its 6×6 size.

📐 Output Size Formula
No padding ⌊(N − F) / S⌋ + 1
With padding P ⌊(N + 2P − F) / S⌋ + 1
N = input  ·  F = filter  ·  S = stride  ·  P = padding
05

Feature Maps & Parameter Sharing

Each kernel produces one feature map. In practice a conv layer runs many kernels in parallel — 64, 128, or 256 — each learning a different pattern (edges, textures, curves). All maps stack depth-wise to form the layer's output volume.

The efficiency win of parameter sharing: the same 3×3 kernel (9 weights) is reused at every spatial position. A fully-connected layer on a 224×224 image needs 150,000+ weights per output neuron. A conv layer with 64 kernels needs just 64 × 9 = 576 weights total.

TRANSLATION EQUIVARIANCE

The same kernel scans everywhere, so if a pattern shifts position in the input, its activation shifts by the same amount in the output. The network detects features regardless of where they appear.

RECEPTIVE FIELD

Each output neuron "sees" only a local patch. Stacking layers grows the receptive field fast — two 3×3 layers = 5×5 view, three = 7×7 — without large, expensive kernels.

🧮 Parameter comparison

Fully-connected on 28×28 MNIST with 128 neurons: 100,352 weights
Conv layer, 32 × 3×3 kernels on same input: 288 weights — 348× fewer.
